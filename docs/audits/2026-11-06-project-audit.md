# Аудит проекта: состав, пробелы, слабые места

Дата: 2026-11-06. Коммит: `b905397`, ветка `main`. Только аудит: код приложения не менялся.

Для следующего агента: начните с раздела «Что делать дальше». Журнал: `docs/AUDIT_LOG.md`, ограничения: `AGENTS.md`.

## Вывод

Интерфейс почти готов, но как блокировщик приложение не работает. Правила создаются, сохраняются и считают время, а реальной блокировки и данных Экранного времени нет. Подтверждённых P0 нет, подтверждённых P1 — 3.

Без аккаунта Apple Developer работаем только в Expo Go (решение заказчика от 2026-11-05). Нативный прототип не предлагать, пока заказчик сам не вернётся к теме: `docs/decisions/001-native-screen-time.md`.

## Что есть

- **Стек:** Expo SDK 58, React Native 0.88, Expo Router, TypeScript.
- **Код:** 146 файлов в `src`, 11 маршрутов, все 267 состояний из макетов.
- **Работает:** знакомство, 4 типа правил, шаблоны, дневник, цели, сохранение на устройстве, сброс данных, локальные уведомления на iOS.
- **Демо:** меню с макетными цифрами доступно только при `__DEV__`.
- **Проверки:** 64 сценария `tools/check-*.mjs`.

Сделано хорошо: сырого `<Text>` нет, захардкоженных цветов в экранах 4, логика вынесена в `src/data`, ошибки хранилища обрабатываются, повреждённая запись сохраняется в резервный ключ.

## P1

### 1. Выбор в знакомстве даёт другой результат — открыто

Шаги: знакомство → «Что вы предпочитаете?» → «Ограничить приложения» → до экрана «Добавим это расписание?».
Ожидание: лимит. Факт: расписание «Рабочие часы 9:00–17:00». Причина: `OnboardingScreen.tsx:21-23`, вариант `limit` создаёт сессию с часами рабочего дня. Проверено в браузере.

### 2. Приложение обещает то, чего не делает — открыто

- Кнопка «Подключить экранное время» ничего не подключает, а Главная потом пишет: «Данные появятся, когда Block подключится к Экранному времени».
- «Сессия началась!» и «Активно» показываются, хотя ничего не блокируется.
- Нигде не сказано, что это прототип.

Проверено в браузере. Сама нативная блокировка в журнале отложена осознанно, находка только о текстах.

### 3. «Напоминания» не срабатывают — открыто

Настройка видна в реальном режиме (`ScreenTimeSettings.tsx:33`) и сохраняется, но `plannedNotifications` её не получает (`notificationPlan.ts`). По правилу проекта неработающее скрывается при `app.live`. Проверено только по коду: прогон в браузере до сохранения не дошёл.

## Чего не хватает

- Изменение приложений и времени у созданной сессии: в деталях есть только название, строгий режим, пауза и удаление.
- Запуск проверок одной командой: нет `npm test` и CI.
- Отчёты о сбоях и свой экран ошибки.
- Миграции данных: `migrate` в `persist.ts` знает только текущую версию, при её смене данные уйдут в резервный ключ и приложение начнётся заново.
- Android: заявлен в README, уведомлений нет, работа не проверялась.

## Сделано плохо

- **Цифры в знакомстве:** остались «8 ч 54 → 1 ч 10», «Instagram 67 ч 15 мин», «18 апр.». Выглядят как данные пользователя. Иллюстрация это или данные, заказчик не подтверждал.
- **Завершённая сессия:** остаётся в списке навсегда, в деталях предлагает паузу и «Отложить».
- **`src/state/app.tsx`:** одно состояние почти на всё приложение, снимок считается при каждой отрисовке (строка 269), значение контекста создаётся заново. Падений нет, код трудно менять.
- **Читаемость:** 415 строк длиннее 300 символов, самая длинная 3052. `RulesScreen.tsx` — 796 строк.
- **Зависимости:** `expo-doctor` не проходит, 6 пакетов отстают. `npm audit`: 9 уязвимостей, 2 высокие (`@expo/cli`, `zod`). Попадают ли они в приложение, не проверялось. `npm audit fix --force` не запускать: откатит Expo до 52. Обновлять через `npx expo install --check`.
- **Устаревшая документация:** README («24 июня», текущая задача), HANDOFF («все данные моковые»), AGENTS («`expo lint` не настроен», хотя `eslint` проходит).
- **Git:** 4 старые ветки слиты в `main`, не удалены. `.git` занимает 256 МБ.
