## Результат

В реестре **267 из 267 состояний HTML**; сопоставлены исходники, браузерные состояния и общие компоненты. Подготовлены 34 контактных листа и просмотрщик с увеличением. Главные задачи: обработка тапа по графику; адаптация низких экранов; единый стеклянный материал; текстовые метрики настроек; исходные SVG уведомлений; завершённые состояния и доступность.

- Визуально: Chrome393×852,267 сопоставленных состояний,315 базовых снимков до финальных уточнений; дополнительные 375/430px и стресс 320px. Отдельно 375×667 для компактных листов. Изображения просмотрены группами, спорные элементы проверены крупнее и по DOM/CSS-замерам.
- Параметры исходного HTML сняты для всех 267 экранов: текст, координаты, размер/вес, line-height, цвет. Файлы в `html/`; текущие снимки и измерения — в `current/`.
- Учитывается различие среды: web safe area равна 0, iOS-клавиатуры/статус-бара в Chrome нет. Одинаковый вертикальный сдвиг корневых экранов относительно iPhone HTML не записан как 267 ошибок.

## Фаза 1 — поведение и доступность контента

### B01 · P1 WEB · Тап по графику показывает неверный тип информации

Воспроизведение: открыть обычный день на Главной → оставить первую страницу героя → нажать столбик 14:00. В `dayToday.chart` есть `h14,v=.208` и пузырь приложения. Открывается **«8 часов вне сети»**, хотя требуется информация о сессии.

Доказательство: [результат нажатия](../reviews/2026-11-03-full-audit/current/chart-hit/P1-chart-tap-14.json), [снимок](../reviews/2026-11-03-full-audit/current/chart-hit/P1-chart-tap-14.png), `UsageChart.tsx:61–64`. В установленном RN Web `PressResponder.onClick` передаёт MouseEvent; его `locationX` отсутствует. Вычисляется `h=NaN`, выбор всегда уходит в offline.

ТЗ: нормализовать координату отдельно для web/native; добавить регрессию занятого 14:00 и пустого часа. **Не считать нативную ветку проверенной этим тестом.** Дополнительно на iPhone проверить hit-testing двух наложенных графиков: визуальный `opacity:0` не отключает интерактивность. Пока это только риск по коду, не вторая подтверждённая P1.

### R01 · Критично для UI · Выбор иконок обрезан на 375×667

Открыть Настройки → Интерфейс → Иконка приложения на 375×667. Видимый лист: y409.33…659. Плитка «Жуть»: y615.31…707.31. Её подпись и нижняя часть скрыты, ScrollView отсутствует. На 320×568 часть пунктов полностью недоступна.

[Геометрия](../reviews/2026-11-03-full-audit/current/core/SE-icon-clipping.json), [снимок 375×667](../reviews/2026-11-03-full-audit/current/core/SE-310.png). Причина: `AppIconPicker.tsx:18`, постоянный `top=409.333`.

ТЗ: вычислять доступную высоту листа, при возможности сохранять исходную 434.667pt; верх поднимать на низком экране. На 393×852 оставить исходную позицию. При нехватке места — общий SheetScrollView. Видимые иконки 62×62 и сетку 4 колонки на 393px не растягивать.

### R02 · Критично для UI · QR/фото пересекаются с footer на низком экране

094 на 375×667: кнопка экспорта перекрывает нижнюю часть карточки.203: кнопка заходит на чёрное поле, подпись ниже доступной части. [QR](../reviews/2026-11-03-full-audit/current/core/SE-94.png), [фото](../reviews/2026-11-03-full-audit/current/core/SE-203.png).

ТЗ: единый каркас «прокручиваемый/сжимаемый контент + footer с safe area». Сохранять геометрию 393×852, уменьшать иллюстрацию или разрешать scroll при недостатке высоты. Не подключать камеру/ИИ и не менять бизнес-логику ради этой правки.

## Фаза 3 — UI/UX без изменения вида по умолчанию

### U01 · Зоны нажатия

Дни недели 39×39 без hitSlop; увеличение длины кода 32×32; отдельные +/-38×38. Довести **зону** до рекомендуемых Apple44×44pt, сохранив визуальные диаметры. Не допускать пересечения соседних hit areas. Native Switch не растягивать, его строку проверять на устройстве. [Автоматические кандидаты](../reviews/2026-11-03-full-audit/small-targets.json) требуют ручной проверки: там есть скрытые слои и размеры web Switch, это не 210 отдельных дефектов.

Apple рекомендует 44pt; минимальный порог WCAG2.2 в 24px — другой критерий. [Apple UI tips](https://developer.apple.com/design/tips/), [WCAG2.2](https://www.w3.org/TR/WCAG22/).

### U02 · Масштабирование и контраст

`T` задаёт `allowFontScaling=false` всем надписям (`typography.tsx:50`). Подготовить политику масштабирования + flex/minHeight/scroll, затем проверить увеличенный шрифт на устройстве; не включать массово без проверки.

Текстовые пары из токенов:

| Текст / фон | Контраст | Цель |
|---|---|---|
| section `#929aa8` / `#f5f8fa` |2.66:1 |Для 20px bold минимум 3:1 |
| value `#7f899a` / `#fff` |3.53:1 |Для мелкого обычного текста 4.5:1 |
| recapDate `#69b6ff` / `#fff` |2.16:1 |Для 14px4.5:1 |

Это конфликт доступности **с самим исходным дизайном**, а не только с реализацией. Изменения цветовых токенов оформлять как согласованную правку дизайна; эталон HTML в соседнем проекте не менять. Disabled/декоративный текст не включать в нарушение без проверки контекста. [Критерий контраста WCAG](https://www.w3.org/TR/WCAG22/#contrast-minimum).

### U03 · Семантика и честные состояния действий

043 и 151/152: PressScale без ролиbutton. Профиль: «Изменить имя» имеет рольbutton, но нет onPress/disabled. Задать корректную семантику работающим CTA; неподключённые операции не показывать как работающие. Это не задача реализовать аккаунт/редактор в дизайн-полировке. VoiceOver/фокус проверить отдельно на iPhone.

-Ранее исправленные scroll-dismiss, onDismiss barrier и размеры native Switch сохранять.

React Native/Expo подходят как основа дальнейшей разработки. Но **267 макетов ≠ готовое полноценное приложение**: системные интеграции и постоянное хранение ещё отсутствуют. Для произвольного нативного кода требуется собственная development build; в этом аудите она не создавалась, зависимости не добавлялись. [Официальное объяснение Expo](https://docs.expo.dev/develop/development-builds/introduction/).
