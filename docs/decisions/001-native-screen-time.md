# 001 — Реальная блокировка: нативный прототип Screen Time

Статус: **предложено, ждёт решения заказчика**. Дата: 2026-11-03.

## Контекст

Пакеты APP-03…APP-05, APP-07, APP-08, APP-12 и APP-23 из [аудита готовности](../audits/2026-11-03-app-readiness.md) требуют системных фреймворков iOS: FamilyControls (разрешение и выбор приложений), ManagedSettings (shield — сама блокировка), DeviceActivity (расписания и лимиты в фоне). В Expo Go их нет и быть не может: нужен собственный нативный код и расширения приложения. Сейчас прототип работает только в Expo Go (правило в `AGENTS.md`).

Что уже сделано без нативного кода: хранение данных, первый вход, удаление правил, живой статус сессий по расписанию, локальные уведомления. Когда появится нативный слой, он подключается к тем же данным (`src/state/app.tsx`, `src/data/sessionSchedule.ts`).

## Решение (рекомендация)

Сделать отдельную ветку с development build и проверить на iPhone одну цепочку: разрешение → системный выбор приложений → shield → временный доступ → повторный shield. Только после неё обещать в интерфейсе реальную блокировку.

Что войдёт в прототип:

1. Config plugin и модуль на Expo Modules API (Swift): `requestAuthorization`, `FamilyActivityPicker`, применение и снятие `ManagedSettingsStore.shield`.
2. Расширения: DeviceActivityMonitor (начало/конец расписания), ShieldConfiguration (вид экрана блокировки), ShieldAction (кнопки на нём). Общие данные — через App Group.
3. Сборка через EAS: `bunx`/`npx eas-cli build --profile development --platform ios`.

Готовые библиотеки (например, `react-native-device-activity`) могут сократить работу, но перед подключением их нужно проверить: поддержка текущего SDK Expo, расширения, лицензия. **Не подтверждено**, какая из них работает с SDK 58.

## Что нужно от заказчика

1. Решение: переходим ли с «только Expo Go» на development build. После перехода Expo Go для этой ветки не подойдёт: на iPhone ставится своя сборка.
2. Аккаунт Apple Developer (платный) и вход в EAS. **Не подтверждено**, достаточно ли development-профиля для Family Controls без отдельного запроса в Apple. Для публикации в App Store разрешение Family Controls (Distribution) запрашивается у Apple отдельно.
3. iPhone с iOS 16+ для проверки: в симуляторе Screen Time не работает полноценно.

## Последствия

- Плюс: реальная блокировка, расписания без открытого приложения, честные экраны 017/107 и shield.
- Минус: дольше цикл проверки (сборка вместо QR в Expo Go), нужен Apple-аккаунт, Android — отдельная работа.
- Веб-превью и проверочные скрипты `tools/check-*.mjs` продолжат работать на моковом слое.
