## 2026-11-03 — новый онбординг 000–025

### P1: FaceTime терялся при создании расписания — исправлено

Шаги: настройка 018 → «Блокировать на работе» → «Социальные сети» → выбрать только FaceTime → продолжить → выбрать способ → добавить расписание.

Конкретный прежний вход: `apps = ['facetime']`. Выражение `['xchat','messages','bereal'].map(id => apps.includes(id))` возвращает `[false,false,false]`. При сохранении только старого массива выбранное приложение отсутствовало в созданной карточке.

Исправление: сохраняется полный `SessionRule.appIds`; общий SessionApps отображает его в карточке и деталях. Старый формат остальных экранов поддерживается.

Регрессия: `tools/check-onboarding.mjs`, проверка `faceTimePreserved`. После полного пользовательского сценария карточка содержит доступное имя FaceTime.

### P1: рядом с созданным расписанием появлялась старая демо-сессия — исправлено

Конкретный прежний сценарий: `setScenario('firstRun')` выбирал `rulesVariants.first` с исходной сессией work; затем addSession добавлял новую сессию. Формула списка `[...createdSessions, ...base.sessions]` показывала две карточки после единственного добавления.

Исправление: завершение онбординга выбирает пустую исходную базу `rulesVariant=onboarding`; отображается только созданная сессия. Пропуск не создаёт расписание.

Регрессия: `tools/check-onboarding.mjs`, сценарий FaceTime проверяет ровно одну карточку «Подробности сессии», отдельная ветка skipSchedule — отсутствие карточек после пропуска.
