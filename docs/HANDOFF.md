# Передача проекта: как велась работа и что дальше

## Текущая задача — продолжать вёрстку экранов из HTML-выгрузок

Свёрстано 28 экранов (список ниже). Впереди ещё ≈200 экранов того же формата: HTML-выгрузки
из Figma, структура папок описана в «Исходники дизайна». Задача следующего этапа:

1. **Получить выгрузки.** Спроси заказчика, где они: ссылка на Figma (читать через Figma MCP),
   отдельный репозиторий с выгрузками или архив в чате. Сам их не ищи и не выдумывай.
2. **Сверить, что уже сделано.** Сравни имена папок выгрузки с таблицей «Свёрстанные экраны».
   Если экран уже свёрстан, но в выгрузке изменился — обнови вёрстку и токены, а не верстай заново.
3. **Верстать по потокам** (номер в начале имени папки — поток, например `17-creating-a-rule-session`).
   Экран, который является состоянием уже существующего (та же Главная или Правила с другими данными),
   делается данными в `src/data/*` и связью в `src/state/app.tsx`, а не новым экраном.
   Новые экраны (создание правила, настройки, онбординг и т. п.) — новые маршруты в `src/app/`.
4. **Продумывать переходы и анимации** между экранами потока: заказчик прямо просил
   появление меню и попапов, реакции на нажатия, связи между состояниями (см. «Анимации»).
5. **Процесс и проверка** — раздел «Процесс: как сверстать новый экран из выгрузки» в конце.
   После каждого пакета: коммит в рабочую ветку, отчёт заказчику со скриншотами
   и списком несостыковок в макетах.

### Связи и переходы (что к чему ведёт)

- **Главная → период:** тап по «Сегодня» → попап (Сегодня / Вчера / Среда, 24 июня) → смена дня
  с плавной сменой контента.
- **Герой → «Качество»:** горизонтальный свайп; карточка статистики и график меняются
  синхронно со свайпом (прозрачность привязана к позиции пейджера).
- **«Обновить»:** загрузка (маскоты, иконка крутится) → данные «13 мин».
- **График:** тап по часу с активностью → «12 минут подряд у экрана…», по пустому → «8 часов вне сети».
- **«Чаще всего»:** пилюля → контекстное меню (Приложения / Активности); «Время с пользой?» → «С пользой»;
  долгое нажатие на приложение → секция «Исключено» под пунктиром (и обратно).
- **Первый запуск:** «Новое начало» → «Понятно» → загрузка → «8 мин»; в Правилах две подсказки
  онбординга («Первое правило добавлено!» → «Добавьте ещё!»).
- **Правила:** секции собираются из данных, пустые скрыты; замок на вкладке показывает
  число активных правил (иконки tab-lock-one/two/badge и контурные badge-2/3).
- **Демо-меню:** долгое нажатие на «⋯» на Главной или в Правилах — сценарии и наборы правил.
  Это служебный инструмент для показа всех состояний, в продукте его быть не должно.

### Анимации

Только встроенный `Animated` (`src/components/motion.tsx`) — без reanimated и других нативных
модулей, чтобы всё работало в Expo Go без dev-сборки.

- `usePresence` — держит оверлей смонтированным на время анимации скрытия.
- `PressScale` — сжатие при нажатии (animated Pressable, стиль и позиция на самой кнопке).
- `FadeIn`, `PopIn` — появление; `animateLayout` — LayoutAnimation для перестройки списков.
- Меню раскрываются из точки привязки (transformOrigin), подсказки выезжают снизу с пружиной,
  столбики графика растут (scaleY от низа), пузыри «попают», полоса лимита заполняется,
  вкладки — `animation: 'shift'`.

## Отклонения от макетов (сознательные)

- Затемнение под подсказками закрывает весь экран; в макете шапка и кнопка «Начать блокировку»
  остаются яркими — непонятно, что тогда можно нажать.
- «0с / 2ч15» в карточке лимита в макете в 0.67 pt от края — отступ 16, как у остального.
- «0с» в рутине почти касается низа карточки (3 pt) — сделано 8.
- Замок на вкладке: в макете Главной без бейджа, в остальных с бейджем — везде по числу правил.
  Для 0 правил заполненного замка нет, стоит простой.
- Подпись «Экранное время» в новых выгрузках стала «Время экрана» — взята новая.

## Несостыковки в макетах (вопросы к дизайну)

- Герой показывает «12 мин», а страница «Качество» того же дня — «Время экрана 20 мин».
  Данные страниц сейчас независимы.
- «Неделя» в выборе периода без макета — не переключается. Для «Среды, 24 июня» нет данных,
  показываются вчерашние.
- Обрезанные края третьих карточек в шаблонах и статьях — растровые полоски, а не контент.
- Исходная иконка `clock-fill` смещена и обрезана — стоит поправить в Figma.

## Известные проблемы и ограничения

- **Шрифт.** iOS — системный SF Pro Rounded (`fontFamily: 'ui-rounded'`, проверено по коду
  RN 0.88: насыщенность сохраняется). Android — Roboto (SF нельзя встраивать по лицензии;
  рекомендация — Nunito через `@expo-google-fonts/nunito` для Android и веба). Веб в Chrome —
  системный шрифт (Inter в контейнере), строки шире, отсюда многоточия на веб-скриншотах.
- `allowFontScaling={false}` во всём тексте ради пиксель-перфекта — Dynamic Type не работает,
  для продакшена вернуть.
- `npx expo lint` не настроен: автонастройке нужна сеть к exp.host, которой в облаке нет.
  `npx tsc --noEmit` чистый.
- На реальном устройстве и в Expo Go не проверялось из облака — только веб-сборка и Playwright.

## Особенности облачного окружения (если продолжать в облаке)

- Закрыты `api.expo.dev`, `exp.host`, `api.ngrok.com`, `drive.google.com` — QR/туннель и EAS Update
  отсюда не работают. Открываются в настройках окружения (Network access → Allowed domains).
- Metro в контейнере не замечает изменения файлов — после правок перезапускать
  `npx expo start --web --clear`.
- Не делать `pkill -f "expo start"` — паттерн совпадает с командой самого шелла и убивает его.
  Искать PID: `pgrep -f "node_modules/.bin/expo start"`.
- Документация Expo (docs.expo.dev) недоступна — API сверялись по типам в `node_modules`.
- RN 0.88: тип ref у View — `ComponentRef<typeof View>`; `StyleSheet.absoluteFillObject` удалён;
  `boxShadow` строкой (в т.ч. inset) поддерживается.

## Процесс: как сверстать новый экран из выгрузки

1. Распаковать выгрузку вне репозитория.
2. Иконки: `node tools/gen-icons.mjs <папка-выгрузок>` — новые добавятся, ручные правки сохранятся.
3. Растр: скопировать новые `assets/art/**/*.png` в `assets/art/`, зарегистрировать в `src/data/art.ts`.
   Если под текстом впечённый блюр — `python3 tools/soften-blur.py`.
4. Токены: сравнить `styles/tokens.css` с `src/theme/tokens.ts` (в выгрузках они меняются).
5. Замеры: `node tools/measure-export.mjs out/ <папки экранов>` — тексты, столбики, пузыри.
   Для компонентов читать стили из `<style>` в index.html.
6. Смотреть `full@3x.png` и верстать во flex с отступами из макета; состояние — через данные
   в `src/data/` и `src/state/app.tsx`, а не копией экрана.
7. Проверка: `npx tsc --noEmit`, веб-сборка + скриншоты Playwright (viewport 393×852),
   сравнение с `screen@3x.png`.
