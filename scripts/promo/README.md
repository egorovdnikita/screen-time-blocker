# Промо-ролик Block для README

Запись настоящей веб-сборки приложения в headless Chrome (Playwright) и монтаж в зацикленный WebP. Ничего не рисуется вручную: каждый кадр экрана — скриншот работающего приложения.

- **Запись** (`record.mjs`): демо-режим (`__BLOCK_DEMO__`, состояние только в памяти, данные вымышленные), экран 393 × 852 pt в 2x. Время подменено часами Playwright и сдвигается ровно на 1/30 с между кадрами, поэтому анимации плавные и одинаковые при каждом прогоне. Кнопки находятся по `aria-label`, точка касания — центр настоящей кнопки.
- **Монтаж** (`compose.py`): холст 1600 × 880, фон GitHub Dark `#0d1117`, обводка `#3d444d`, скругление 20 pt, телефон в центре. Курсора нет — касания показаны матовыми кольцами (та же кривая, что в промо Agent Pulse). Камера приближает меню периода и диалог удаления и возвращается к общему плану. Последние 0,3 с экран сводится к первому кадру: первый и последний кадр совпадают.
- **Сценарий**: Главная → период «Вчера» и обратно «Сегодня» → «Блокировать» → «Прямо сейчас» → «Начать» → сессия в Правилах → подробности → удаление с подтверждением → Профиль → Главная. Удаление возвращает состояние к началу, поэтому петля бесшовная.

## Как воспроизвести

Временные файлы и окружения — вне репозитория.

```sh
npx expo export -p web                                   # веб-сборка в dist/
npm i --prefix /tmp/block-promo-env playwright@1.56      # нужен установленный Google Chrome
python3 -m venv /tmp/block-promo-py && /tmp/block-promo-py/bin/pip install pillow
PROMO_ENV=/tmp/block-promo-env node scripts/promo/record.mjs /tmp/block-promo
/tmp/block-promo-py/bin/python scripts/promo/compose.py /tmp/block-promo docs/assets/block-demo.webp --keys
```

Запись ≈ 2,5 мин, монтаж ≈ 5 мин. `--keys` сохраняет контрольные кадры каждые 0,5 с и кадры стыка в `/tmp/block-promo/keys/` для просмотра глазами. После монтажа скрипт декодирует готовый WebP и проверяет длительность, бесконечную петлю и совпадение первого и последнего кадра.

Сжатие: по умолчанию WebP без потерь (≈ 19 МБ за 22 с) — только так первый и последний декодированные кадры совпадают точно. `--lossy --quality 90` даёт ≈ 5 МБ, но на стыке остаётся шум сжатия. Кодирование — libwebp из Pillow, кадры подаются потоком; ffmpeg не нужен.
